# Cashu Spilman Channel -- Real Crypto Demo

In-browser demonstration of a complete Cashu Spilman channel lifecycle between Alice (buyer) and Charlie (seller), running against the real [testnut.cashu.exchange](https://testnut.cashu.exchange) mint. No mocked crypto, no stubbed HTTP calls. The signatures, blinding, and proof construction are the real deal.

## What This Demonstrates

Click "Run Full Lifecycle" and watch the debug panel scroll through five phases:

1. **Channel Open** -- Alice and Charlie perform ECDH over secp256k1 to derive a shared channel secret. Alice fetches active keyset info from testnut, derives a channel ID from a SHA-256 hash of all channel parameters plus the shared secret.

2. **Channel Fund** -- Alice requests a Lightning mint quote from testnut (auto-paid). She creates deterministic blinded outputs using P2BK derivation, posts them to the mint, receives blind signatures, then unblinds those signatures into spending proofs.

3. **Payment 1 (10 sat)** -- Alice creates a Schnorr-signed balance update using her private key tweaked with a channel-secret-derived scalar. The signature commits to `SHA256(channel_id || "|" || 10)`.

4. **Payment 2 (20 sat)** -- Same mechanism, cumulative balance now 30 sat. Signature commits to `SHA256(channel_id || "|" || 30)`.

5. **Cooperative Close** -- Charlie splits the funding proofs into receiver outputs (30 sat for him) and sender refund outputs (70 sat for Alice), all deterministically derived. Posts a `/v1/swap` to testnut with the original funding proofs as inputs. Gets back fresh proofs for both parties.

## Architecture

### File Structure

```
spilman-real/
  index.html        Page shell: Alice panel, Charlie panel, lifecycle controls, debug output
  style.css         Dark theme styling (GitHub-inspired color tokens)
  src/
    main.js         Entry point. Creates wallets, wires buttons, runs lifecycle phases
    wallet.js       Alice and Charlie wallet objects. WASM for channel ops, crypto.js for keygen/close
    channel.js      State machine: INIT -> FUNDED -> CLOSING -> CLOSED (plain functions)
    crypto.js       Key generation, denomination splitting, deterministic outputs for close contexts
    cdk-wasm-bridge.js  Lazy WASM loader (cdk_wasm_bg.wasm, ~2.3 MB)
    cdk-wasm-adapter.js Format conversion (camelCase ↔ snake_case), P2BK blinding scalars, SIG_ALL witness
    mint.js         HTTP wrappers for testnut.cashu.exchange NUT-01/02/03/05 endpoints
    ui.js           DOM update helpers for wallet panels and debug log
    test-vectors.js     Test vector validation (crypto.js vs Rust)
    test-vectors-cdk.js Test vector validation (cdk-wasm vs Rust, 194 checks)
  wasm/
    cdk_wasm.js         WASM JS glue (auto-generated by wasm-pack)
    cdk_wasm_bg.wasm    WASM binary (~2.3 MB, compiled from cdk-spilman Rust crate)
```

### What's Real (Production-Grade Crypto)

These operations use cdk-wasm (compiled from the same Rust crate as the SatsAndSports reference) and produce output identical to the Rust implementation:

- **Channel secret**: `compute_channel_secret` via WASM (domain-separated ECDH)
- **Channel ID**: `channel_parameters_get_channel_id` via WASM (SHA-256 of serialized params)
- **Funding token amount**: `compute_funding_token_amount` via WASM (exact amount accounting for fees)
- **Funding outputs**: `create_funding_outputs` via WASM (deterministic blinded outputs with P2PK spending conditions)
- **Proof construction**: `construct_proofs` via WASM (blind signature unblinding + DLEQ parsing)
- **Balance update signing**: `spilman_channel_sender_create_signed_balance_update` via WASM (full SIG_ALL serialized swap request hash)
- **Cooperative close witnesses**: `sign_with_tweaked_key` via WASM with P2BK stage1 blinding scalars (2-of-2 P2PK multisig)
- **Real mint HTTP interaction** against testnut.cashu.exchange (keysets, keys, mint quote, mint, swap with witnesses)

### What's Simplified (PoC Only)

- **Both wallets in the same page.** Alice calls `charlie.acceptPayment()` directly. No network between them.
- **In-memory only.** Nothing persists across page reloads.
- **No unilateral or timeout close path.** Only cooperative close is implemented.
- **No multi-channel support.** One channel per page load.
- **No DLEQ verification.** The mint's blind signatures include DLEQ proofs but `construct_proofs` parses them without verifying.
- **Alice mints fresh tokens each run.** She does not reuse existing proofs from a wallet or fund from a Cashu token (`compute_channel_from_token` not used).
- **Not using WasmSpilmanBridge/WasmSpilmanClientBridge.** We call low-level WASM bindings and hand-roll the orchestration. The SatsAndSports examples use high-level bridge classes that manage lifecycle, storage, and networking internally.
- **Cooperative close uses crypto.js for output construction.** The "receiver"/"sender" context outputs still use JS-side deterministic output creation; only the final `construct_proofs` call goes through WASM.
- **No keyset caching.** Keyset info fetched from mint each run.

### crypto.js Functions Still in Use

| JS Function (`crypto.js`) | Used For | Rust Source |
|---|---|---|
| `generatePrivateKey()` / `getPublicKey()` | Wallet key generation | `SecretKey::random()` / `PublicKey::from_secret_key()` |
| `getDenominationAmounts()` | Binary amount splitting for close outputs | Amount decomposition into powers of 2 |
| `createDeterministicOutput()` | Close context outputs ("receiver", "sender") | `create_deterministic_output_with_blinding()` |
| `bytesToHex()` / `hexToBytes()` | Hex conversion throughout | Utility |

All other crypto operations (channel secret, channel ID, funding outputs, proof construction, balance updates, witness signing) now go through cdk-wasm.

## How to Run

### Local HTTP Server

The demo uses ES module imports via `esm.sh`, so it needs an HTTP server (not `file://`).

```bash
# From repo root
python3 -m http.server 8000 --directory docs/private/demos/spilman-real
```

Then open [http://localhost:8000/](http://localhost:8000/).

### Test Vectors (from Rust spike)

If you have the Rust toolchain configured and the `spilman` feature enabled:

```bash
cargo test -p tollgate-net --test cdk_spilman_test_vectors --features spilman -- --ignored --nocapture
```

This captures fresh test vectors from the Rust implementation that the JS demo can validate against.

### Browser Console

The demo exposes wallet objects on `window` for interactive exploration:

```javascript
window.alice          // Alice's wallet object (keys, channel state, proofs)
window.charlie        // Charlie's wallet object
window.runVectors()   // Test vector validation (stub, returns pass)
```

Wallet objects have these useful methods: `openChannel()`, `fundChannel()`, `createPayment(amount)`, `getBalance()`, `cooperativeClose()`. Channel state is at `wallet.channel` with fields `id`, `status`, `capacity`, `balanceToReceiver`, `fundingProofs`, `history`.

## Compare and Contrast

### What we built on

Every crypto function in `crypto.js` is a 1:1 translation from the [SatsAndSports/cashu_spilman_channels](https://github.com/SatsAndSports/cashu_spilman_channels) Rust crate (`cdk-spilman/src/params.rs`). The JS produces identical output to the Rust — we captured test vectors from the Rust spike test (`cdk_spilman_bridge_spike.rs`) to verify.

The channel state machine (`channel.js`) mirrors the lifecycle in the Rust `SpilmanChannelManager`. The mint HTTP wrappers (`mint.js`) follow the [Cashu NUT specs](https://github.com/cashubtc/nuts).

### What exists and how we differ

**SatsAndSports/cashu_spilman_channels** ([GitHub](https://github.com/SatsAndSports/cashu_spilman_channels/tree/main/examples)) has four reference implementations — Rust (Axum server), TypeScript (Express), Python (Flask), and Go. Each runs a "pay-per-character ASCII art" server where a client opens a Spilman channel and pays per request. The TS example uses `SpilmanClientBridge` / `WasmSpilmanBridge` — high-level classes that manage the full channel lifecycle (storage, state machine, networking) inside WASM. Our demo calls low-level WASM bindings and orchestrates the lifecycle in JS, which is more verbose but exposes each step explicitly for educational purposes.

**cashu-ts** ([GitHub](https://github.com/cashubtc/cashu-ts)) is the official TypeScript Cashu wallet library. As of v4.2.1 it does not support Spilman channels. Our long-term goal is to contribute Spilman support upstream.

**Option A simulator** (in this repo at `docs/private/demos/spilman-simulator.html`) is a 20-step educational walkthrough of the Spilman channel lifecycle. It uses simulated SHA-256 instead of real elliptic curve cryptography and does not interact with a real mint. Our demo (Option B) uses real crypto and a real mint, but with a simpler UI. The goal is to combine the educational depth of Option A with the real-crypto fidelity of Option B.

| | This demo | SatsAndSports TS example | cashu-ts | Option A simulator |
|---|---|---|---|---|
| Real crypto | Yes (cdk-wasm + @noble) | Yes (WasmSpilmanBridge) | Yes (no channels) | No (simulated) |
| Real mint | Yes (testnut) | Yes (local) | N/A | No |
| Architecture | Low-level WASM bindings + JS orchestration | High-level bridge classes | Library API | N/A |
| Close paths | Cooperative only | Cooperative + unilateral + timeout | N/A | All (simulated) |
| DLEQ | No | Yes (via bridge) | N/A | N/A |
| Setup | Open URL | Clone + build + 2 terminals | npm install | Open URL |
| Educational UI | Split-screen, step-by-step | Terminal logs | Library API | 20-step walkthrough |

### What we copied vs what is ours

- **WASM binary**: Same `cdk_wasm_bg.wasm` compiled from the same `cdk-spilman` Rust crate. Identical crypto output.
- **Channel lifecycle flow**: Our JS orchestration mirrors the phases in the reference implementations. Same order: open → fund → pay → close.
- **P2BK blinding scalar derivation**: `deriveBlindingScalar()` in cdk-wasm-adapter.js mirrors `params.rs:539-562` exactly.
- **SIG_ALL message construction**: `computeSigAllMessage()` mirrors Cashu crate `nut03.rs:101-119`.
- **Mint HTTP calls**: Standard Cashu protocol. Same endpoints every Cashu wallet uses.
- **Channel orchestration**: Ours. We call individual WASM bindings and wire them together in JS. The reference uses `WasmSpilmanBridge`/`SpilmanClientBridge` classes that handle this internally.
- **UI design**: Ours. Split-screen layout, dark theme, token visualization, signature details.

## Migration Roadmap

**Destination**: Native Spilman channels in [cashu-ts](https://github.com/cashubtc/cashu-ts). See [ADR-0005](../../adr/0005-native-cashu-ts-spilman-strategy.md) for full strategy.

### Phase 0 - Complete (Hand-Rolled Crypto)

- [x] 16 crypto functions in `crypto.js`, 1:1 translation from cdk-spilman Rust
- [x] Real ECDH, Schnorr, blinding, proof construction against live mint
- [x] Test vector capture from Rust (`cdk_spilman_test_vectors.rs` -> `test-vectors.json`)
- [x] Cooperative close lifecycle
- [x] In-browser demo with no build step

### Phase 1 - Complete (cdk-wasm Bridge)

- [x] Host `cdk_wasm.js` + `cdk_wasm_bg.wasm` alongside demo
- [x] WASM test vector validation (194/194 checks passing)
- [x] SIG_ALL message hash via `spilman_channel_sender_create_signed_balance_update` - closes G1
- [x] Exact-amount mint quotes via `compute_funding_token_amount` - closes G7
- [x] Spending condition witnesses for cooperative close - closes G10
- [x] 6/6 Playwright E2E tests passing against real mint
- [ ] Evaluate switching from low-level bindings to `WasmSpilmanBridge`/`WasmSpilmanClientBridge` (Wave D)
- [ ] Add DLEQ verification pass-through via cdk-wasm - partially closes G2
- [ ] Add unilateral close path via cdk-wasm - partially closes G3
- [ ] Channel state persistence (IndexedDB) - closes G4
- [ ] Peer separation (iframe/worker) - closes G5
- [ ] CI oracle: Playwright test comparing cdk-wasm and `crypto.js` on identical inputs

### Phase 2 - Native cashu-ts Spilman

- [ ] Contribute Spilman module to cashu-ts using `@noble/curves`/`@noble/hashes` (same deps cashu-ts already uses)
- [ ] Full DLEQ verification in pure TS - closes G2
- [ ] Full unilateral + timeout close in pure TS - closes G3
- [ ] Revocation logic - closes G6
- [ ] Multi-channel support - closes G8
- [ ] Demo switches from hand-rolled `crypto.js` to cashu-ts Spilman module
- [ ] cdk-wasm remains as CI oracle only (no longer needed at runtime)

### Drift Prevention

Every phase maintains byte-for-byte equivalence with the Rust reference (cdk-spilman):

1. **Shared test vectors** - Rust captures, JS validates (see `TEST-VECTORS.md`)
2. **Protocol version strings** - domain separation prefixes are shared constants
3. **CI oracle** - cdk-wasm vs TS output comparison on every PR
4. **Gap table** - every simplification tracked with target phase (see ADR-0005)
